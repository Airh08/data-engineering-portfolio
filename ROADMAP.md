# Roadmap

## Phase 00 — Foundations
Git, Linux/Bash, Python tooling, packaging, testing, logging and code quality.

## Phase 01 — SQL
Advanced SQL, analytical queries, windows, CTEs, deduplication and query optimization.

## Phase 02 — Python for Data Engineering
APIs, files, validation, error handling, retries, configuration and reusable packages.

## Phase 03 — Databases & Data Modeling
OLTP vs OLAP, normalization, dimensional modeling, star schemas and slowly changing dimensions.

## Phase 04 — ETL / ELT
Multi-source ingestion, incremental loads, idempotency, metadata, auditability and failure recovery.

## Phase 05 — AWS
S3, IAM, Lambda, Glue, Athena, Redshift, EventBridge, Step Functions, SQS/SNS and CloudWatch.

## Phase 06 — Orchestration
Apache Airflow: DAG design, scheduling, retries, backfills, sensors, dependencies and operations.

## Phase 07 — Analytics Engineering
dbt models, tests, snapshots, incremental models, documentation and lineage.

## Phase 08 — Distributed Processing
PySpark, partitioning, joins, skew, file sizing, Spark SQL and performance optimization.

## Phase 09 — Lakehouse
Parquet, Delta Lake / Apache Iceberg, medallion architecture, MERGE, schema evolution and time travel.

## Phase 10 — Streaming
Kafka, event-driven ingestion, consumers/producers, delivery semantics and real-time pipelines.

## Phase 11 — Infrastructure as Code
Terraform modules, environments, state, reusable infrastructure and deployment patterns.

## Phase 12 — CI/CD & DataOps
GitHub Actions, automated tests, linting, SQL/dbt validation, Terraform validation and deployment workflows.

## Phase 13 — Data Quality
Schema, completeness, uniqueness, freshness, referential integrity, anomaly checks and quality reporting.

## Phase 14 — Observability
Pipeline health, freshness, volume, latency, failures, alerts, SLAs/SLOs and operational dashboards.

## Phase 15 — Enterprise Capstone
A complete retail data platform evolving from a local batch pipeline into a cloud-native, distributed, observable and production-oriented platform.

### Definition of done for every phase

Each project should include:

- Business problem
- Architecture diagram
- Source and target data contracts
- Implementation
- Tests
- Failure scenarios
- Operational considerations
- Performance considerations where applicable
- README with setup and execution instructions
- Architecture Decision Records when meaningful
